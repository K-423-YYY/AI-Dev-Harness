# 项目开发计划（示例模板）

> 首次运行 `run.sh` / `run.bat` 时会自动生成 `docs/plan.md`。本文件只是格式参考，不会参与执行。

## 目标

用一句话描述要交付的产品或功能，例如：一个支持用户登录和仪表盘的电商网站。

## 需求补全

- 目标用户：谁在使用
- 核心场景：最重要的 1-3 个使用流程
- 范围外内容：本期明确不做的事情
- 技术选型：前端、后端、数据库、部署方式

## 任务分解

| # | 任务 | 优先级 | 状态 |
|---|------|--------|------|
| 1 | 初始化 frontend 与 backend 脚手架 | P0 | [ ] |
| 2 | 实现用户注册、登录与鉴权中间件 | P0 | [ ] |
| 3 | 实现仪表盘数据接口 | P1 | [ ] |
| 4 | 实现仪表盘页面与响应式布局 | P1 | [ ] |
| 5 | 补充单元测试、集成测试和 E2E | P1 | [ ] |

## 验收标准

- 用户可注册、登录、退出，未登录访问受保护页面会跳转登录页
- 仪表盘展示真实数据，接口带分页和错误处理
- `scripts/verify.sh` / `scripts/verify.ps1` 全部通过

## 验证方式

每完成一个任务就更新状态并运行验证脚本；验证失败时定位错误、修复后重跑。
