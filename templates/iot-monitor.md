# 项目模板：智能家居 / 远程监测应用（方案 A1 IoT 需求）

> 使用方式：把本模板内容作为参考，让引擎生成计划书时指定"按 iot-monitor 模板"。

## 目标
一个面向智能家居 / 远程监测场景（如气压监测）的移动端应用，基于 MQTT 实现端到端双向数据流。

## 需求补全
- 目标用户：需要远程监测环境参数（气压等）的个人/家庭用户
- 核心场景：传感器数据采集 → MQTT 上云 → 移动端实时监测 → 下发控制指令
- 范围外：本期不做视频监控
- 技术选型：通信 MQTT 协议（轻量可靠）、端侧传感器采集（气压监测）、移动端应用软件架构

## 任务分解
| # | 任务 | 优先级 | 状态 |
|---|------|--------|------|
| 1 | 通信架构设计：MQTT 协议选型、Topic 规划、QoS 级别 | P0 | [ ] |
| 2 | 端侧：气压传感器数据采集与上报模块 | P0 | [ ] |
| 3 | 服务端：MQTT Broker 与数据存储 | P0 | [ ] |
| 4 | 移动端：实时监测界面与告警 | P1 | [ ] |
| 5 | 移动端：指令下发（端到端双向数据流闭环） | P1 | [ ] |
| 6 | 断线重连与消息可靠性保证 | P1 | [ ] |

## 验收标准
- [ ] 端到端双向数据流转闭环：传感器 → MQTT Broker → 移动端 → 下发控制
- [ ] 断线重连与消息可靠性保证
- [ ] 移动端实时监测界面与告警
- [ ] scripts/verify 全部通过

## 验证方式
每完成一个任务更新状态并运行验证脚本；验证失败时定位错误、修复后重跑。
